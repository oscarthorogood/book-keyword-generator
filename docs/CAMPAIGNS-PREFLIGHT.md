## Design-relevant findings beyond the table

1. **`competitor_keywords` is a live-breaking bug today, unrelated to the campaigns feature.** Five files read/write a table that does not exist in the live DB (V3/V4). This will throw at runtime the first time `lib/competitorStore.ts`'s keyword functions or the reverse-ASIN import route are hit. Recommend `sql/20-fix-competitor-keywords-drift.sql` (Prerequisite C, per spec §3) ship first and alone, exactly as the spec already plans — but note it's not hypothetical, it's actively broken.
2. **`sql/19` was never applied live.** The `competitor_asins_source_check` constraint live is two migrations behind the committed file (`sql/16`'s parity fix was applied, `sql/17`/`18` metadata/presets were applied, but `sql/19`'s live-source expansion was not). Any "Generate ASINs" run backed by a live source (`serpapi`, `zenrows`, autocomplete sources) will hit a constraint violation right now. This should probably be folded into the same corrective migration as #1, or called out separately — it's outside the campaigns spec's scope but was surfaced by this audit and blocks a currently-shipped feature.
3. **Prerequisite B (negatives per named campaign) is mostly already done.** `lib/bulksheet.ts` already attaches the negative list to every campaign it generates, not just Descriptive. The only real remaining work from §2 is adding the `campaign`/`ad_group` scope tag to `NegativeKeyword` and threading it through to the right entity row — a much smaller task than "fix negatives-per-campaign" implies.
4. **§0.1's own reconciliation note in `docs/ARCHITECTURE.md`** (lines 22-33) already documents that the doc has drifted from the real app before (wrong entry point, wrong wizard fields) and says "code wins over docs." The `§23.2`/`§23.7` citations (V9) are the same kind of drift, just not yet reconciled — worth a follow-up doc fix, but out of scope for this gate.
5. **`lib/bulksheet.ts`'s current CSV export is live and tested**, not a stub. Prerequisite A (§1) needs to fold in the exceljs `*-upload.xlsx` builder alongside — not instead of — this existing CSV path, since `app/api/books/[id]/keywords/export/route.ts`, `app/api/books/[id]/competitors/export/route.ts`, and `tests/listingPipeline.test.ts` all depend on today's shape.

No code, migrations, or files other than this one were written for this task.
